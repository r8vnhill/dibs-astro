### `tsup.config.ts`

Critical configuration:

```ts
external: [/\.svg$/],  // Keep SVG imports verbatim; don't bundle them
```

This tells esbuild to preserve relative `.svg` import paths in the output, allowing Vite to resolve them naturally.

### `src/svg.d.ts`

```ts
declare module "*.svg" {
    const Component: import("astro").AstroComponentFactory;
    export default Component;
}
```

Provides type information for TypeScript so `src/index.ts` can be type-checked in isolation (without relying on the
Astro app's `astro/client` reference).

### Validation Scripts

#### `scripts/copy-assets.mjs`

- Finds all `.svg` files in `src/`
- Copies them to `dist/` in parallel using `Promise.all`
- Runs after tsup as a post-build step

#### `scripts/assert-pack-files.mjs`

- Validates required files present (README.md, package.json, dist/index.js, etc.)
- Validates no blocked files (src/, scripts/, config files)
- Validates SVG count parity: `src/*.svg` count == `dist/*.svg` count in tarball
- Scale-invariant: works with any number of icons, no manual updates needed

## Implementation Notes

- **Build step**: The two-step build (tsup + copy-assets) is necessary because tsup does not copy non-code assets. The
  `external` configuration ensures SVG references remain relative.
- **Type safety**: `src/svg.d.ts` is essential; without it, TypeScript cannot resolve the 1,521
  `import ... from "*.svg"` lines in the generated barrel.
- **Pack validation**: Using count parity rather than an enumerated file list makes the script maintainable as icons are
  added/removed without touching the validation logic.
- **No Node.js consumer test**: Unlike other packages, there is no `validate-packed-consumer.mjs` because SVG transforms
  require Astro's Vite pipeline. Validation happens in Phase 5 via the Astro dev/build process.
