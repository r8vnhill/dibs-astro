# Agent Guide: @ravenhill/astro-icons

## What is this package?

`@ravenhill/astro-icons` is a workspace package that holds 1,521 SVG icon files and exports them as Astro
SVG components. It is consumed by the Astro app via the `$icons` path alias.

## Directory structure

```
packages/astro-icons/
  src/
    index.ts              (auto-generated barrel with 1,521 re-exports)
    svg.d.ts              (module declaration for *.svg imports)
    acorn.svg
    address-book.svg
    … (1,519 more SVG files)
  dist/
    index.js              (generated by tsup; keeps SVG references external)
    index.d.ts            (generated by tsup)
    index.js.map          (source map)
    *.svg                 (copied post-build from src/)
  scripts/
    copy-assets.mjs       (post-build: copies src/*.svg to dist/)
    assert-pack-files.mjs (validates tarball contents)
  package.json
  tsconfig.json
  tsup.config.ts
  README.md
  AGENTS.md (this file)
```

## Key implementation notes

### 1. Auto-generated barrel

`src/index.ts` is generated by `generate-icons-index.js` (at the monorepo root). It looks like:

```ts
export { default as Acorn } from "./acorn.svg";
export { default as AddressBook } from "./address-book.svg";
// … 1,519 more
```

**Do not edit manually.** To regenerate after adding/removing SVGs:

```sh
# From monorepo root
pnpm generate-icons
```

### 2. SVG type declaration

`src/svg.d.ts` declares `*.svg` imports as `AstroComponentFactory`:

```ts
declare module "*.svg" {
    const Component: import("astro").AstroComponentFactory;
    export default Component;
}
```

This is a standalone type declaration for this package. The Astro app's own `src/env.d.ts` has a similar declaration via
`/// <reference types="astro/client" />`, but the package needs its own so TypeScript can resolve SVG imports when
type-checking the barrel in isolation.

### 3. Build with external SVG imports

`tsup.config.ts` includes:

```ts
external: [/\.svg$/],
```

This tells esbuild to **keep SVG imports verbatim** in the output rather than trying to bundle them. The resulting
`dist/index.js` contains relative imports like:

```js
export { default as Acorn } from "./acorn.svg";
```

Vite (in the consuming Astro app) will then resolve these relative imports normally.

### 4. Post-build SVG copy

The build script runs two steps:

```json
"build": "tsup && node scripts/copy-assets.mjs"
```

`tsup` emits the barrel but does not copy asset files. `copy-assets.mjs` runs after, copying all `src/*.svg` to `dist/`
so the published package contains both the barrel **and** the SVG files.

### 5. Tarball validation

`scripts/assert-pack-files.mjs` validates package contents:

- Required files: `README.md`, `package.json`, `dist/index.js`, `dist/index.d.ts`, `dist/index.js.map`
- No source leak: `src/` is excluded (via `package.json` `files` field)
- No scripts leak: `scripts/`, `tsup.config.ts`, `tsconfig.json` excluded
- SVG parity: count of `dist/*.svg` in tarball equals count of `src/*.svg` on disk

This is scale-invariant: no need to update the check when icons are added/removed.

### 6. No consumer test script

Unlike other packages (e.g., `shiki-core`), there is no `scripts/validate-packed-consumer.mjs`. SVG transforms require
Astro's full build pipeline; a plain Node.js consumer cannot load SVG files. Instead, end-to-end validation is done in
Phase 5 by running the Astro dev server and production build.

## Common tasks

### Add or remove an icon SVG

1. Place the new `.svg` file in `src/` or remove an unwanted one
2. Run `pnpm generate-icons` from the monorepo root
3. The barrel (`src/index.ts`) is regenerated automatically
4. Commit the SVG and the updated barrel

### Rebuild the package

```sh
pnpm --filter @ravenhill/astro-icons build
```

Check that `dist/` contains:

- `index.js`, `index.d.ts`, `index.js.map`
- 1,521 `.svg` files (or however many are in `src/`)

### Validate the package

```sh
pnpm --filter @ravenhill/astro-icons check
```

This runs build, typecheck, lint, and pack validation.

### Test package publication

```sh
pnpm --filter @ravenhill/astro-icons pack:dry-run
```

This creates a fake tarball and lists its contents without publishing.

## When to contact humans

- **If barrel generation fails**: Check that `generate-icons-index.js` paths are correct and `src/*.svg` files exist.
- **If pack validation fails**: Check that `dist/` was populated after build (copy-assets.mjs ran), and that the SVG
  count matches.
- **If the Astro app can't find icons**: Check that `$icons` alias in root `tsconfig.json` points to
  `./packages/astro-icons/src/index.ts`.
- **If icons don't render in the browser**: The issue is likely in the Astro app's SVG pipeline, not in this package.
